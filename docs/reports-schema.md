# Canopée Database Schema — `reports`

Source of truth for the `reports` table. The `.dbml` file is authoritative; the dbdiagram view is a mirror for visualization.

Related issue: [Issue]: Design reports table schema (#25)

---

## Conventions

(Same conventions as the rest of the Canopée database — see `users-schema.md`)

- IDs are `uuid`, generated by the database.
- Timestamps are `timestamptz` (timezone-aware). Never use bare `timestamp`.
- `created_at` on every table, defaulting to `now()`.
- Enum values are lowercase snake_case.
- Foreign keys are named `<table_singular>_id` (e.g. `user_id`).
- Citizens are not users. Public reporters interact with the app without accounts; their email is captured on the report itself (`reporter_email`).

## Tables

### `reports`

Public and authenticated user reports (incidents, fauna/flora observations). One row per submitted report.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | `uuid` | PK | Internal report id. |
| `event_number` | `integer` | unique, auto-increment (DB-generated) | Human-readable report number. Never set manually. |
| `user_id` | `uuid` | nullable, FK → `users.id` | Filled if the reporter has an account. |
| `reporter_email` | `text` | nullable | Filled if the reporter is a citizen (no account). |
| `category` | `report_category` | not null | Report type. Fauna/flora distinction is made on the front-end via this field — not a separate table. |
| `description` | `text` | nullable | Free-text report details. |
| `photo_url` | `text` | nullable | Optional for general reports; required for fauna/flora categories (enforced at the application level, not the DB level). |
| `latitude` | `decimal` | not null | |
| `longitude` | `decimal` | not null | |
| `resolved_at` | `timestamptz` | nullable | `null` = open, populated = resolved. No separate status enum. |
| `created_at` | `timestamptz` | not null, default `now()` | |

**DB constraint:** one of `user_id` or `reporter_email` must be present.

**Application-level rules (not enforced by the DB):**
- Fauna/flora categories require an authenticated user (`user_id` must be present; `reporter_email` alone is not accepted).
- Citizens (`reporter_email` only) can only submit `general` category reports.
- Photo is required for fauna/flora categories, optional for general reports.

## DBML

```dbml
Table reports {
  id uuid [pk]
  event_number integer [unique, increment, note: 'Auto-incremented by DB, human-readable, never set manually']
  user_id uuid [note: 'Nullable FK -> users.id. Filled if reporter has an account']
  reporter_email text [note: 'Nullable. Filled if reporter is a citizen (no account)']
  category report_category [not null, note: 'Enum TBD with Canopée - will include fauna/flora observation types']
  description text [note: 'Nullable']
  photo_url text [note: 'Nullable. Required for fauna/flora categories - enforced at app level']
  latitude decimal [not null]
  longitude decimal [not null]
  resolved_at timestamptz [note: 'Nullable. null = open, populated = resolved']
  created_at timestamptz [not null, default: `now()`]

  Note: '''
  Constraint (app/DB level): one of user_id or reporter_email must be present.
  '''
}

}
```
